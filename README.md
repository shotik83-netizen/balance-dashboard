# Баланс взаиморасчётов

Готовое автономное HTML-приложение для чтения Excel с SharePoint. Дизайн и устройство рабочего пространства основаны на проекте [Финансовая модель](https://github.com/shotik83-netizen/model): меню подрядчиков слева, ключевые показатели в хедере, выбор договоров, администрирование внизу.

## Запуск

1. Скачайте **index.html** и откройте в Chrome или Edge. Сервер и установка не нужны.
2. Исходная книга из задания загружается автоматически при открытии приложения. **Обновить источник** повторно читает подключённую книгу; **Открыть Excel** позволяет выбрать актуальный файл.
3. «Все подрядчики» открывает общий баланс по подрядчикам. Выбор подрядчика открывает его баланс по договорам; отметьте нужные договоры в раскрывающемся блоке.
4. Настройте валюту, НДС, единицы и округление. По умолчанию: млн, целые числа для сумм и процентов.
5. Выгрузите **Excel**, **CSV** или текущую страницу через **Печать / PDF**.

Инструкция встроена в приложение и доступна уже на первом экране.

Основной акцент оформления: RGB **0, 140, 149** (`#008C95`).

## Что реализовано

- Полный общий баланс: строки и порядок показателей из Excel, колонки подрядчиков, общий итог слева.
- Баланс каждого подрядчика по договорам; сохранены отступы, итоговые строки и пустой разделитель исходника.
- Настройка «Скрывать подрядчиков без данных в выбранном исходном листе» включена по умолчанию. Подрядчики без значений скрываются из меню и общего баланса; нули остаются данными. Настройка сохраняется в конфиге и распространяется на выгрузку.
- Четыре варианта исходных отчётов; варианты без данных подрядчика недоступны и не заменяются нулевыми балансами.
- Печать сначала показывает предпросмотр: видимый баланс, мост и авансы копируются с экранными шрифтами, цветами и размерами, затем пропорционально уменьшаются на один альбомный A4. Предпросмотр и печать используют одну композицию, без повторного переноса колонок. Ключевые показатели из хедера не включаются.
- Выгрузка повторяет выбранный вид: по подрядчикам или по договорам. Проценты свода рассчитываются из сумм числителя и знаменателя.
- Шрифты и начертания заголовков / показателей согласованы с текущей «Финансовой моделью».
- Рубли / валюта договора; с НДС / без НДС через соответствующие листы исходника.
- Единицы / тысячи / миллионы; округление до целых, 1 или 2 знаков.
- Баланс с НДС на втором уровне при первом запуске. Группирующие статьи раскрываются отдельно по нажатию, включая вложенные разделы. Третий уровень скрыт; выбор 1/2/3 меняет видимость строк и выгрузку, не меняя итогов. Один выбор варианта баланса по центру футера; договоры подрядчика открываются по выбору в левом меню.
- Поиск подрядчиков и показателей, чекбоксы договоров, выбор всех / снятие выбора. Итог и KPI пересчитываются по отмеченным договорам. Галочка «Итого по подрядчику» скрывает общую колонку и оставляет выбранные договоры.
- Настройки ссылок, листов, диапазонов, карт колонок и строк, названий, валют и курсов. Галочки видимых подрядчиков сохраняются в конфиге и определяют состав меню, KPI, общего баланса и выгрузки. Новые подрядчики скрыты до включения; уведомление ведёт в администрирование.
- Мост оплат справа от баланса подрядчика: контракт → оплачено по актам → выданные авансы → ГУ → КЗ → остаток оплат. Расчёт: контракт − оплаты − авансы + ГУ + КЗ, с исходными знаками ГУ и КЗ. Учитываются отмеченные договоры, выбранный лист, валюта, единицы и округление. Разные валюты не складываются; отсутствие исходного показателя делает мост недоступным. В администрировании настраиваются строки для каждой ступени; на листе НЗП оплаты берутся из строк 12+13, авансы из 14+16.
- Пять строк зачёта авансов по каждому отмеченному договору: выданный аванс / контракт; зачтённый аванс / принятые акты (КС); незачтённый аванс / (контракт − акты); акты × процент выданного аванса; зачтённый аванс из источника с исходным знаком. Блок по умолчанию под мостом; выбор «Под балансом» сохраняется в конфиге. Нулевая база и пустые исходные значения не заменяются нулями.
- Ключевые показатели в хедере; их можно скрыть в администрировании. Баланс занимает основную область экрана; ширина договоров ограничена.
- Поиск в хедере, формат чисел и статус подключения с цветной точкой в футере.
- Источники, обновление и администрирование доступны только при включённом режиме редактирования.
- Автоматическое скачивание конфигурации при применении изменений.
- Импорт конфига и скачивание автономного HTML с внесёнными настройками.
- Экспорт числовых значений и отдельных итогов по валютам.
- Чтение сохранённых результатов формул Excel, обработка пустых данных и ошибок.

## SharePoint

Все стили и скрипты встроены в `index.html`; внешние JS/CSS/CDN не используются.

1. Разместите `index.html` и `balance-config.json` рядом на SharePoint. Конфиг читается автоматически; для старых архивов также поддерживается `config/balance-config.json`.
2. Включите «Режим редактирования», откройте «Администрирование» и укажите прямую ссылку на XLSX и рабочую папку. Адрес конфига необязателен, если файл лежит рядом с HTML.
3. Нажмите «Применить и скачать настройки». Вручную замените `balance-config.json` на SharePoint скачанным файлом, сохранив точное имя. При закрытии администрирования с изменениями конфиг также скачивается; нажатие на фон больше не закрывает настройки.
4. Закройте и заново откройте страницу приложения. Ссылки загрузятся из конфига, затем по ним загрузится Excel. Относительные ссылки внутри JSON разрешаются относительно расположения JSON, а не HTML.
5. Для работы одним HTML нажмите «Скачать HTML с настройками» и замените страницу приложения скачанным `index.html`. В нём сохранены все введённые настройки. Если заполнен адрес внешнего конфига, он имеет приоритет — его тоже нужно обновить; оставьте это поле пустым, если используете только встроенные настройки HTML.
6. Если конфиг расположен отдельно, укажите прямой URL в настройках и скачайте HTML с ним либо откройте `index.html?config=<закодированный URL JSON>`. Приложение читает конфиг и Excel один раз при открытии. Последующие обновления — по кнопке.

Указанная ссылка на внешний конфиг имеет приоритет над соседними файлами; ошибка его чтения отображается явно. Отсутствие обоих стандартных конфигов (HTTP 404) допускает запуск исходной версии. Страница входа/просмотра вместо JSON или XLSX, запрет доступа и ошибки чтения не подменяются встроенными данными. Для прямых XLSX-ссылок на sharepoint.com приложение добавляет параметр `download=1`.

Режим доступа выбирается в настройках: текущий сайт, с авторизацией или без авторизации. Для защищённого SharePoint предпочтительно размещение HTML и XLSX на одном origin. При запрете CORS или чтения по ссылке скачайте исходный XLSX и откройте его вручную. Пароли, токены и ключи в конфиг не записываются.

## Данные и расчёты

В приложение встроен именно пользовательский источник с актуальностью **15.09.2026**. Книга автоматически открывается при запуске, если в настройках не указана ссылка на внешний Excel. Ссылка SharePoint имеет приоритет; при ошибке её чтения встроенная книга не подставляется. **Обновить источник** повторно читает текущий встроенный или внешний файл.

Четыре листа исходника имеют разную структуру и охват. Рубли без НДС читаются из самостоятельного отчёта НЗП. Валютные листы содержат только восемь договоров; подрядчики без данных в выбранном листе по умолчанию скрыты. При отключении настройки отсутствие подрядчика показано явно. Валюта USD валютных листов задана по заголовку исходника и может быть изменена отдельно для каждого договора. Автоматического пересчёта всех строк по единой ставке НДС нет.

Промежуточные итоги Excel исключены из суммирования. Колонки без номера договора, которые не являются промежуточными итогами, показаны отдельно с буквой колонки. Итоги складываются до округления. Разные валюты не суммируются. Доля НЗП в итоге рассчитывается как НЗП / выполнение по выбранным договорам. Пустые ячейки обозначаются «Нет данных», нули — прочерком. `*` у итога означает неполные данные.

Пересчёт формул выполняется в Excel до сохранения и размещения файла. Приложение читает сохранённые значения. Формулы без результата и ошибки источника не заменяются нулями.

Приложение не записывает данные в localStorage, sessionStorage, IndexedDB или cookies. Данные живут в оперативной памяти открытой вкладки. Сохранение конфигурации и отчётов — через скачивание файлов. Права на исходные данные регулируются SharePoint; раздел администрирования не имитирует систему разграничения доступа.

## Структура проекта

| Файл / папка | Назначение |
| --- | --- |
| `index.html` | Готовое автономное приложение |
| `config/balance-config.json` | Начальная конфигурация |
| `data/source.xlsx` | Оригинальная книга из задания |
| `src/` | Исходники интерфейса, чтения XLSX, экспорта и настроек |
| `build.py` | Сборка единого HTML без дополнительных пакетов |
| `tests/verify.cjs` | Проверки реального источника и функциональности |
| `tests/source-expected.json` | Независимые сохранённые значения из Excel для сверки |
| `docs/source-analysis.md` | Особенности исходника и результаты проверки |

Сборка: `python3 build.py`. Для проверки нужен Node.js 22+ и пакет `xml-js`: `node tests/verify.cjs`. Пакет используется только тестами; самому приложению он не нужен.

Репозиторий публичный и приложение опубликовано на GitHub Pages с разрешения пользователя. HTML содержит встроенную финансовую книгу. Для выпуска версии без встроенного источника удалите `data/source.xlsx` перед сборкой и используйте загрузку актуального файла или ссылку SharePoint.
